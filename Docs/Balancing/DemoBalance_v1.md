# 트리키 요트 — 스팀 데모용 임시 밸런싱 v1

> 목적: 스팀 데모 전에 수치를 **한 곳에 모으고**, **초반을 조금 어렵게** 잡는다.
> 수치는 확정값이 아닌 **시작값**이다. 시뮬레이션 결과를 보고 ±20% 안에서 조정한다.

## 0. 전제

| 항목 | 값 |
|---|---|
| 데모 범위(가정) | 바이옴 2개: 숲 → 선택한 바이옴 1개. 두 번째 보스까지 |
| 난이도 목표 | 숲 1막에서 처음 하는 플레이어의 약 40%가 탈락. 두 번째 바이옴 보스 처치율 약 25% |
| 원칙 | 수치는 코드 상수가 아니라 데이터(BalanceConfig + 기존 테이블)에서 읽는다 |

## 1. 지금 상태 (코드에서 확인한 값)

| 항목 | 현재 | 위치 |
|---|---|---|
| 플레이어 최대 체력 | 100(기본), 캐릭터별 initialHP | `PlayerStatus`, `CharacterData` |
| 몬스터 공격 턴 | 모든 몬스터 2턴 고정 | `Enemy.Initialize` (`MaxAttackTurn = 2`) |
| 몬스터 체력 성장 | `maxHp × 1.05^(stage-1)` (전체 스테이지 누적) | `Enemy.Initialize` |
| 몬스터 공격력 성장 | `baseAtk + stage/2` | `Enemy.Initialize` |
| 몬스터 원본 수치 | 숲 일반 HP 10~45 / ATK 1~2, 숲 보스 HP 80 / ATK 6 | `Monster_Data_List.json` → MonstersSO |
| 굴리기 횟수 | 2 | `DiceManager.maxRerolls` |
| 족보 배수 | 1.0 / 1.2 / 1.4 / 1.5 / 1.7 / 1.8 / 2.0 / 2.5 | `DiceManager.mult*` |
| 몬스터 골드 | 일반 30~60, 엘리트 40~250, 보스 500~5000 | 몬스터 데이터 |
| 피규어 드롭률 | 일반 0.2, 엘리트 0.4, 보스 1.0 | 몬스터 데이터 |
| 상점 가격 | 피규어 250~500, 주사위 10~200, 스낵 20~200, 코팅 120~170, 위성 100, 스탬프 150, 티켓팩 300 | `Shop_Stock_Table.json` |
| 상점 리롤 | 100 | `ShopManager.rerollCost` |
| 판매가 | 구매가의 50% | `InventoryManager` |
| 휴식 회복 | 최대 체력의 30% | `Map_Table.json` Rest_Heal_Percent |
| 보상 등급 가중치(1~25) | 일반 68 / 레어 24 / 에픽 6 / 전설 2 | `Reward_Loot_Table.json` gradeWeight |

**문제점**
- 숲 몬스터가 너무 약하다(HP 10~45). 첫 턴 원콤이라 긴장감이 없다.
- 체력·공격력 성장이 "전체 스테이지 수" 기준이라 바이옴 순서와 맞지 않는다. 공격력 `+stage/2`는 후반에 폭주한다.
- 공격 턴이 전부 2턴이라 일반·엘리트·보스의 체감 차이가 없다.
- 보스 골드(500~5000)가 상점 가격 대비 과하다.
- 몬스터 수치가 JSON, SO, 씬 세 군데에 흩어져 있을 수 있다. 실제로 게임에서 쓰는 값을 먼저 확인해야 한다.

## 2. 설계 기준 (목표 체감)

초반 플레이어 1턴 기대 피해: 주사위 5개 합 약 17 × 배수 1.2~1.5 ≈ **20~28**(아이템 없음 기준)

| 전투 | 플레이어 턴 수(목표) | 맞는 횟수(목표) | 체감 |
|---|---|---|---|
| 일반 | 2~3턴 | 0~1회 | 운 나쁘면 한 대 맞음 |
| 엘리트 | 4~5턴 | 2회 | 체력 관리가 필요 |
| 보스 | 6~8턴 | 3~4회 | 준비 안 되면 짐 |

## 3. 변경 수치 (v1 시작값)

### 3-1. 플레이어
| 항목 | 현재 | v1 |
|---|---|---|
| 기본 최대 체력 | 100 | **80** (캐릭터 initialHP는 80 기준 ±10으로 맞춤) |
| 시작 골드 | (확인 필요) | **100** |
| 굴리기 횟수 | 2 | 2 (유지) |
| 휴식 회복 | 30% | **25%** |

### 3-2. 몬스터 공격 턴 (등급별로 분리)
| 등급 | 현재 | v1 |
|---|---|---|
| 일반 | 2 | **3** |
| 엘리트 | 2 | **2** |
| 보스 | 2 | **2**. 체력 50% 이하에서 **1턴**으로 줄어드는 2페이즈 |

### 3-3. 몬스터 체력·공격력 기준값 (바이옴 1 = 숲, 스케일 적용 전)
| 등급 | HP | ATK | 비고 |
|---|---|---|---|
| 일반 | **45~70** | **6~9** | 한 대 = 최대 체력의 약 10% |
| 엘리트 | **120~150** | **12~15** | |
| 보스 | **240~280** | **16~20** | 2페이즈 포함 |

- 몬스터 간 상대 비율은 지금 데이터 비율을 유지한다(약한 놈은 계속 약하게).
  각 등급 안에서 지금 값의 최솟값~최댓값을 위 범위로 선형 변환한다.

### 3-4. 성장 공식 (전체 스테이지 → 바이옴 단계 + 바이옴 안 진행도)
- `HP = baseHp × tierHp[biomeTier] × (1 + 0.04 × nodeIndexInBiome)`
- `ATK = baseAtk × tierAtk[biomeTier] + floor(nodeIndexInBiome / 6)`
- tierHp: [1.0, 1.6, 2.4, 3.4], tierAtk: [1.0, 1.4, 1.9, 2.5]
  - biomeTier = 몇 번째 바이옴인지(0부터). 데모는 0, 1만 사용
- 기존 `1.05^(stage-1)`, `+stage/2` 는 제거한다(설정으로 켜고 끌 수 있게 남겨도 됨).
- 눈먼 점술가 패널티(다음 적 체력 ×2), 튜토리얼 체력 상한은 유지한다.

### 3-5. 골드
| 항목 | 현재 | v1 |
|---|---|---|
| 일반 처치 | 30~60 | **20~35** |
| 엘리트 처치 | 40~250 | **60~90** |
| 보스 처치 | 500~5000 | **150 + 바이옴 클리어 보상 150** |
| 여정 주사위 골드 | 눈 1당 10 | **눈 1당 5** |
| 코인 주사위 / 다이아 스탬프 | 눈 1당 10 / 5 | 유지 (시뮬 후 재검토) |

목표: 첫 상점 도착 시점(Shop_Row) 보유 골드 **약 350~450** → 피규어 1개 + 작은 아이템 1개를 고민하는 수준

## 4. 검증 지표 (시뮬레이터 목표)

봇: 매 턴 기대 피해가 가장 큰 주사위를 남기고 굴리고, 상점에서는 살 수 있는 것 중 가장 비싼 피규어를 산다.

| 지표 | 목표 |
|---|---|
| 숲 일반 전투 평균 턴 | 2.3~3.0 |
| 숲 엘리트 평균 턴 | 4~5 |
| 숲 보스 도착 시 남은 체력 | 평균 40~55% |
| 숲 탈락률 (봇 1000판) | 35~45% |
| 두 번째 바이옴 보스 처치율 | 20~30% |
| 첫 상점 도착 골드 | 350~450 |

목표를 벗어나면 몬스터 HP(1순위) → ATK(2순위) → 골드 순서로 조정한다.

## 5. 변경 이력
- v1: 최초 작성 (데모 전 임시)
- v1.1: 봇 시뮬레이션(1000판) 결과로 ±20% 안에서 3회 조정해 적용. 결과는 `SimResult_v1.md`.
  - 몬스터 기본 수치(`Monster_Data_List.json`, Void 제외)
    - 3-3 범위로 선형 변환한 뒤, **보스·엘리트 HP·ATK를 x0.8**
    - 숲 보스 버그베어 192/13, 숲 엘리트 96~120 / 11
    - 일반 몬스터는 3-3 그대로 (숲 45~70 / 6~9)
  - 엘리트 등급: 숲에 엘리트가 없어 `Goblin_Warrior`, `Guardian of Meadow`를 엘리트로 올림
  - 성장 공식(`BalanceConfig`)
    - 바이옴 안 전투당 HP **+3.2%** (0.04 → 0.032)
    - tierHp **[1.0, 1.28, 2.4, 3.4]**, tierAtk **[1.0, 1.12, 1.9, 2.5]** (2단계만 x0.8)
    - `nodeIndexInBiome` = 이 바이옴에서 이미 치른 전투 수
  - 골드
    - 몬스터 골드 **x1.2**
    - 바이옴 클리어 보상 **180**
    - 여정 주사위 골드 눈 1당 **6**
    - 시작 골드 100은 유지
  - 휴식 회복·여정 골드는 `Map_Table.json`에서 `BalanceConfig`로 옮김
  - 피규어 드롭: 페퍼민트 없이 처치해도 등급별 확률로 드롭한다(페퍼민트 포획은 100% 유지). 확률은 `BalanceConfig` 값을 쓴다.
  - 캐릭터 시작 체력: 70~110 → 70~90 선형 변환 (번트헤드 90 / 클로비스 85 / 크리스티나 80 / 코비코 75 / 폰 70). 캐릭터 선택값이 실제로 적용되게 함
  - 피규어 등급은 데이터에 없어 기존 가격으로 나눔: 250 → 일반 150, 300 → 레어 250, 350·400 → 에픽 400, 500 → 전설 600
  - 남은 문제 (±20% 밖)
    - 숲 탈락률 78% (대부분 보스 2페이즈), 두 번째 보스 처치율 0%
    - 엘리트 5.2턴, 첫 상점 골드 259
    - 보스 2페이즈를 끄거나 보스 HP를 더 25% 줄이면 숲 탈락률은 31~38%가 된다. 두 번째 보스는 바이옴 2단계 배율을 다시 설계해야 한다.
